# cortex-retrieve

What Cortex hands an agent before it starts searching. So far it holds what a prompt points at and
the seeds of a retrieval (what its words find, what the session has been doing, earlier work like
it, and the dark code beside those), the graph that activation spreads over, the spreading itself,
the gate's rule, and the reading of a file that lends its lines only when it is the file the index
read.

## What it must never do

- Inject anything it is not sure of: its gate stays silent unless independent signals agree, and
  silence is what a missing signal gives, never a guessed span.
- Show a line number or a line of code it has not just checked against the file on disk.
- Let the order rows came in, a hash map's order or a clock reach what it renders.
- Write the store: it reads, and the daemon's single writer records what it rendered.

## Entry points

| Item | What it is |
| --- | --- |
| `PromptTerms`, `Mention` | What a prompt points at: the words a search looks up (its identifier tokens, split as the index splits names, less the words that name no place, digits alone, single letters and the extension of a path named with a folder in it, which says what language a file is in, not where it is), and the mentions that may name a file or a symbol exactly: a path with the line a stack frame or traceback gives, a name written as code (an underscore, a capital inside, digits among letters, parts joined by `::`, backticks), or both for a word like `service.ts` or `Config.load` |
| `Graph`, `NodeInput`, `LinkInput`, `Weighing`, `Standing`, `GraphError` | The graph of the store's nodes and links, as compressed sparse rows per kind of link, nodes numbered in id order. A link weighs its kind's weight from `retrieval.type_weights` times its strength in 0 to 1: a reference's confidence, a co-change confidence, a co-access link's weight faded by `learning.link_decay` to the latest task and taken over the most a link can weigh, a folder's hold on its files. Co-change links run the way history shows them; every other link both ways. A file is joined to each of its symbols both ways at the containment weight. Links of one kind between the same nodes add up; a link to itself, to a node not given, or of no weight is left out; a node given twice keeps the first of its kinds and files in their order, and a symbol whose file is no file node has none. A graph past 32-bit node numbers or link counts is refused (`GraphError`). `out_weight` is a node's links' sum over every kind, by which spreading divides them; `peak_links` gives each link's heaviest single part, what one stored link carries alone; `symbols_of` lists a file's symbols, whatever containment weighs; `type_weights` the weights it was weighed by. Each node carries its standing: its interest brought forward by `learning.interest_decay` to the latest task, the tier that puts it in (a landmark as the last task to choose them left it), and whether a work order may point at it (not a generated or vendored file). Its view by files, which two-stage spreading runs over, is built on first use and kept with it; `prepare_by_files` builds it ahead, and `is_prepared_by_files` says whether it is built. A graph's view takes no part in whether two graphs are equal |
| `lexical`, `LexicalMatch`, `FileMatch`, `MAX_HITS` | The prompt's words looked up by BM25: the 50 best rows, each a seed weighed by its score over the best's; a word more than one row in twenty holds (and more than twenty rows) is not looked up but still counts. A path or a name the prompt writes exactly, found in the repository, is a seed of weight 1: the file (by its path, the one path ending in it, or the one path an absolute path ends in), the symbol at its line, the symbols of a name five or fewer share. Each file's match is the share of the prompt's words it holds, weighed by inverse document frequency, over at least twice the weight of a word one row in a hundred holds; a named file matches fully; the top lexical score is the best file's |
| `session`, `SessionMatch`, `ReadSpan`, `EDITED_WEIGHT`, `READ_WEIGHT`, `SEEDED_READS` | What the session has been doing: the code its tasks edited, its subagents' edits included, seeded at 1; the code its latest 10 reads touched, its own, at 0.4; a node edited and read carries both. A stretch of lines counts for the symbols it touches, or its file when it touches none or names no lines. The files it edited, and every span it read since its context was last compacted, with the short hash of what the index held for the file then. A read or edit that failed counts for nothing |
| `similar`, `SimilarMatch`, `SIMILAR_BAR`, `SIMILAR_WEIGHT` | Earlier work like the prompt's: each cluster of earlier tasks whose first words, as many as the prompt has and at least five, overlap the prompt's words by a Jaccard score of 0.3 or more seeds its files at 0.6 times that score, a file of several such clusters taking the best; the best score of any cluster, at the bar or not, is kept for the gate |
| `exploration`, `EXPLORATION_WEIGHT`, `MAX_EXPLORED` | The dark structural neighbours of the ten strongest seeds (no tier as of the latest task, not seeds themselves), 0.05 each, at most 20: strongest seed first, then heaviest link, then by node |
| `seeds`, `SeedQuery`, `Seeds`, `summed`, `shares` | One retrieval's seeds: what the prompt's words, the session (none for a question asked outside one), the work tree's uncommitted diff and earlier work found, the dark neighbours of those, and the vector they make. Per node the sources' weights add and each sum is divided by the whole, so the vector sums to 1; when nothing weighs anything there is no vector |
| `scored_files`, `with_symbols`, `ScoredFile`, `LANDMARK_PRIOR`, `INTERESTING_PRIOR` | Each file activation reached, scored: its node's activation and its symbols', each times its prior (1.5 for a landmark, 1.25 for an interesting node, 1 for the rest, as of the latest task), best first and then by node; its symbols best first; a generated or vendored file left out. `with_symbols` scores the symbols of the first files again from another spreading's activation, the files keeping their own scores |
| `Support`, `Evidence`, `STRUCTURAL_FLOOR`, `COACCESS_FLOOR` | The independent kinds of evidence behind a file: the prompt's words found it; earlier work like the prompt changed it; or a reference (tied at 0.8 or more), a co-change link (either way round) or a co-access link (its faded weight at least 0.05) joins it or one of its symbols to another file the seeds of the words, the session or earlier work point at, each link held to its floor alone, in the weights the graph was weighed by. Exploration's seeds are no evidence, nor are the uncommitted diff's, which the work tree holds whatever the prompt is about. `partners` names, for one kind of link, the other seed files it joins a file to, each with its heaviest such link, heaviest first |
| `spans_of`, `outline_of`, `is_in_context`, `Span`, `Outlined`, `MAX_SPANS_PER_FILE` | Which lines of a file to point at. A file's symbols, as the store outlines them (`outline_of`), are as strong as their score, or their interest when none scored. Each strong symbol is taken out to the nearest function, method, test, class, interface or type around it, itself included, and cut to `retrieval.span_max_lines` centred on the middle of the strongest symbol within; spans that overlap or touch are joined while they fit the cap, else the weaker is passed over; at most two a file. A file with no symbols is shown whole when it fits the cap. A span read since the session's last compaction, over lines covering it or whole, while the index still holds the hash it held then, is in context |
| `read_graph`, `GraphSettings`, `RetrieveError` | The graph of everything the store holds, weighed by `retrieval.type_weights`, co-access links faded by `learning.link_decay` to the store's latest task, each node's standing as of that task |
| `spread`, `Network`, `Activation`, `SPREAD_THRESHOLD`, `L1_TOLERANCE`, `MAX_PUSHES` | Spreading activation from seeds over a `Network` (the graph, or a view of it): an approximate personalized PageRank by local push, with the restart probability given (`retrieval.teleport`). A node is pushed while it has the threshold left to spread (first 1e-5), in the order nodes came to have it; when none has but more than 1e-3 is left in all, the threshold is lowered tenfold and pushing goes on, so a spreading that ends on its own is within 1e-3 (L1) of exact PageRank. It stops cut short after 50,000 pushes or at a deadline. A node never keeps more than its exact value, and what is left to spread bounds the shortfall |
| `two_stage`, `Staged`, `STAGED_FILES` | Spreading in two stages, as huge repositories spread: first over the graph's view by files, each file standing for itself and its symbols (their links to other files, each landing in the file it reaches, the weights into one file added; a seed on a symbol starts at its file), the files scored as in one stage; then from the seeds again over the nodes of the 30 best files and the links among them alone, which gives those files' symbols their scores and reaches nothing else. Files past the 30th keep no symbol. Both stages' activations are kept. A graph whose view by files would hold more links than a 32-bit offset counts is an error, and nothing is spread |
| `decide`, `Verdict`, `Rule`, `Shut`, `AGREEING_KINDS`, `LEXICAL_BAR` | The gate, which weighs `cortex_core::GateFeatures`. The cold-start rule lets a work order through when two independent kinds of evidence support one top file and the prompt's best-matching file scores at least 0.5 (plus the self-check's raise), or when the session is plainly continuing its own work; otherwise it is silent and says why |
| `features_of`, `Found`, `GATED_FILES`, `MASSED_FILES` | The gate's features from one retrieval: the top lexical score; the share of all kept activation the best five files hold; the most kinds of evidence behind one of the best three files and the kinds behind any of them; the best overlap with earlier work; the recent precision the caller gives; and whether the session continues its own work (one of the best three was edited in it and the prompt's words found it too) |
| `uncommitted`, `UncommittedMatch`, `UNCOMMITTED_WEIGHT` | What the work tree is changing and has not committed: the file nodes of the uncommitted diff the daemon read, each seeded at 0.8 on the file, whatever the session; a node the graph does not hold is left out. A top-3 file of the diff that the prompt's words match is continuing work, as an edit earlier in the session is |
| `reason_of`, `Reason`, `ItemEvidence`, `MAX_REASON_CHARS` | Why a file is listed, the strongest true reason first: named in the prompt; edited earlier in this session; the prompt's words it matches; an uncommitted change; changes with another file in so many of its commits; refers to, or is referred to by, another file by a reference tied at 0.8 or more; changed in similar earlier tasks; worked on with another file before; read earlier in this session. At most 60 characters, a long name cut with `...`; a file with none is not listed. `Reason::kind` names what kind of reason it is (`cortex_core::ReasonKind`), without its words, as the store keeps it |
| `render`, `WorkOrder`, `Item`, `ItemSpan`, `Basis`, `Limits`, `Rendered`, `MAX_WORK_ORDER_CHARS` | The work order as the agent reads it: a header saying what agreed; "Start here", the items whose code is shown, with their lines, symbol and reason; "Also likely", the rest by path and lines; "Current code", the shown spans' lines numbered. Each item's file is read and hashed as it is written: one that changed since the index read it, is past the size cap or has nothing indexed to check it against lends no lines and is listed by path alone, and one that is not a regular file that opens for reading (deleted, a link, a folder, or held by another program) is not listed. Control characters (but tabs) and characters that reorder or hide text (`cortex_core::is_hidden`) are taken out of the code shown; an item whose path or reason holds one is not listed. An agent's reminder tag (`cortex_core::REMINDER_TAGS`) is never written, since the agent would get it altered or take it for its own words: a span whose lines hold one once cleaned is neither shown nor named, and an item whose path, symbol or reason holds one is not listed; the primer names no landmark whose path holds one. Held to the files, the lines a span and the token cap given (never above 1,200 tokens), two spans a file and 8,000 characters, by shedding code, then the later items; nothing when no item can be listed as it is or even the first does not fit; the same order always the same text |
| `primer`, `MAX_PRIMER_LANDMARKS`, `MAX_PRIMER_TOKENS` | What an agent is told when a session starts: the repository's mode and its source files and lines, rounded to two significant digits and grouped by thousands; up to eight landmark files, the most interesting, listed by path; and one line on what Cortex adds, which in tiny mode is nothing. Nothing of the session or the time, so the same store gives the same bytes; none before the first index sets the mode, or past 400 tokens |
| `retrieve`, `Request`, `Retrieval`, `Outcome`, `Silence`, `SMALL_MODE_MAX_TOKENS` | One retrieval from a prompt to what the agent is told: the seeds, the spreading (`retrieval.teleport`, the request's deadline), the scores, the gate's features and rule, and, when it opens, the files listed and the work order written from them, held to `retrieval.max_tokens` (400 in small mode). Silent, and saying why, in tiny mode, when nothing is found, when the gate stays shut, and when no file can be listed, none fits, or none of the three best files the gate weighed is shown. The files it lists are those the work order wrote, each with the spans whose lines it wrote. In huge mode the spreading runs in two stages (`two_stage`), the gate weighing the first stage's activation. The gate's cold-start rule is the same in every mode: small mode's higher bar is one on a probability, which only a calibrated model gives. The caller decides whether to inject: a held-out task is retrieved for in full and given nothing |
| `locate`, `Location` | The same engine without the gate, for a question asked of it directly: in every mode, with or without a session, the files found (at most the limit asked), each with its spans and its true reason, and the gate's features and what it would have said; nothing when the question points at nothing. A question whose spreading ran out of time names no file, since which files it had reached by then is the clock's doing: the answer says only that it ran out of time |
| `listed`, `Listing`, `Listed`, `LOOKED_AT_PER_LISTED` | The files a work order lists: down the scored files, at most four looked at for each that may be listed, each with its spans out of the session's context and the strongest true reason, which names the other file a link joins it to, with the commits the two share as the store counts them; a file whose every span is in context, or of which nothing true can be said, is passed over |
| `CheckedFile`, `Unchecked` | A repository file read whole, never through a link at its own path and never past a size limit, only when its BLAKE3 hash is the one the index stored, so a link among the folders above it cannot lend other bytes either; its lines numbered from 1 as the index counts them (`cortex_index::count_lines`) |

## Tests

```sh
cargo test -p cortex-retrieve
cargo bench -p cortex-retrieve --bench spread
```

Weights are worked out by hand in each test's comment; a property checks that the same rows in any
order give the same graph. Spreading is checked against exact personalized PageRank, computed by
power iteration over a petgraph copy of each random graph (`tests/push.rs`); the gate against a
table of cases; reading against files changed, too large or not files at all. The `spread`
benchmark spreads over generated graphs of 10,000, 100,000 and 1,000,000 nodes (files of five
symbols, each referring to two symbols elsewhere, each file changing with three others and
worked on with two) from five seeds, and spreads in two stages over the largest, its view by files
built beforehand as the daemon builds it.
