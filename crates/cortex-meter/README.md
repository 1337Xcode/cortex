# cortex-meter

What agents' work costs in tokens, read from the transcripts the agents write as they work.

## What it must never do

- Keep or log anything a transcript says beyond the counts, the model's name and the time: no
  prompt, no answer, no tool's input or output.
- Read a transcript twice over: a tail reads each whole line once, from where it stopped.
- Guess a count: a line missing one of its counts is passed over, not taken as zero.

## Entry points

| Item | What it is |
| --- | --- |
| `Tail`, `Turn`, `MAX_LINE_BYTES`, `MAX_RECENT_RESPONSES` | Reads a transcript from the byte offset where the last read stopped, the whole lines within a given number of bytes a read (a line longer than that read on to its end, as far as 64 MiB), and returns the responses those lines report, in order: a line cut short waits until it is whole. Each response is a `Turn` numbered by its order among the transcript's responses, from 1, with its time in UTC milliseconds, model, counts, how it was served and a hash of its message id, which a copy of it in another transcript keeps. A response written on several lines, one per content block, counts once, and so does a side conversation's line that replays it under another request: a message id names one response. A later copy with more tokens comes again under the same number, its counts and service replacing the earlier ones. A response of the `<synthetic>` model counts nothing. The latest 64 responses are remembered for this. A file shorter than where the last read stopped was written again and is read from its start, numbered as before. A line longer than 64 MiB is passed over |
| `TranscriptFormat`, `format_of`, `Claude`, `Codex`, `Earlier` | How an agent writes its transcript's lines, and the folders it keeps them in, one format per agent, Claude Code's and Codex's. Claude Code's are kept in `~/.claude/projects` and, when `CLAUDE_CONFIG_DIR` holds an absolute path, in its `projects` folder too. A Claude Code response is an `assistant` line whose message carries `usage`: the message id tells it apart, `timestamp` dates it, and the counts are the uncached input, the cache writes (the five-minute and one-hour writes added up when both are given, with the one-hour part kept apart; otherwise the flat count, its split unknown), the cache reads, the output and the reasoning within it (`output_tokens_details.thinking_tokens`). How it was served is read from `usage.service_tier`, `speed` and `inference_geo`, each only when it is text that is a name; a value of another type is unknown and leaves the line readable. Codex's rollout files are kept in `~/.codex/sessions` and, when `CODEX_HOME` holds an absolute path, in its `sessions` folder too. A Codex response is a `token_usage_record` line: `response_id` tells it apart, `timestamp` dates it, and its `usage` gives the whole input, the part read from the cache and the part written to it (the input at the full price is the rest), the output and the reasoning within it. The line names no model: the latest `turn_context` line before it does, which the reading keeps (`Earlier`); a response before any is not counted. A format says whether its transcripts record the call that compacts a session (`records_compaction`): Codex's do, Claude Code's do not. Every count must be there |
| `PriceTable`, `ModelPrices`, `Rates`, `Billed`, `Cost`, `Unpriced`, `SHIPPED_PRICES`, `load_or_write`, `load`, `PricingError` | Estimates what a response cost from a table of prices in US dollars per million tokens: the table Cortex ships (`pricing.toml`, copied from Anthropic's pricing page with the date it was read), written to the user's file the first time one is needed (whole, private to the user, and linked into place so that it never replaces a file already there and no reader sees it half written) and read from there after, the user's prices winning (`load` reads the file without ever writing it, none when there is no file, for a caller that only shows prices). A model's standard prices, its fast mode prices where it has them, a multiplier for US-only inference where it offers it, and prices for long prompts where it charges them apart; a dated model id takes its undated prices. Costs are whole picodollars, so they add up exactly. A response is priced only when the table knows everything its price depends on (its model, the standard tier, its speed, where it ran, and how its cache writes split); otherwise it has no estimate and says why. Tokens only: per-use charges for server tools are not counted |
| `Response`, `Usage`, `Service`, `SYNTHETIC_MODEL` | One response as a line reports it, its counts, and how it was served: its service tier, speed and where it ran, each kept only when the line names it with a name |
| `cache_breaks`, `CacheBreak`, `BreakCause`, `BreakContext` | Where a session's conversations lost the prompt cache: a response that wrote more than half its cached input (cache writes and reads together) anew while reading under half of what the response before it read, each conversation (the session's, each subagent's) taken apart in turn order. Each break gets the first cause that holds of a model switch between the two responses, a compaction of that conversation between them, a gap longer than the cache lives (an hour when every cache write of the conversation so far was for an hour, as the transcript splits them, five minutes otherwise), and text Cortex gave between them that reached the agent; none when nothing known explains it. A time on either edge of the span counts, the hook's clock and the transcript's not agreeing to the millisecond |
| `Activity`, `receipt`, `SessionReceipt`, `TaskReceipt`, `Tally`, `Estimate` | Adds up what one session's tasks took. A task runs from its prompt to its stop, or to the next task's start when it never stopped; each response, the session's and its subagents', belongs to the task whose span holds its time, and the rest are counted apart. Per task: turns, tool calls, every input token (read fresh, written to the cache and read from it), the uncached part, cache reads and writes, output, and the cost summed over the responses the price table can price, the others counted by the reason they have none; the session's tool calls, outside its tasks too; and whether its agent's transcripts are read at all (`is_metered`), since a session whose agent has no reader has no usage that says nothing; and how many of its compactions its total leaves out (`compactions_left_out`), those whose calls its agent's transcripts do not record; each estimate's part spent on cache writes (`cache_write_picodollars`); and the session's cache breaks (`cache_breaks`), from the times each conversation compacted and the times Cortex's texts reached the agent. What Cortex added is counted from its injections that reached the agent (`InjectionRecord::was_delivered`): each task's texts (its work orders, warnings, read hints, recaps, strict mode's reasons and the keep-lists given to a compaction's summary), the session's primers, and all of them together; one the gate kept back, held out or not written in time adds nothing |
| `Precision` | Of the work orders that reached the agent and whose tasks ended, how many were labelled and how many of those were used; its share, none before any was labelled |
| `weighed`, `compare`, `Weighed`, `Comparison`, `Compared`, `BOOTSTRAP_RESAMPLES` | The holdout comparison. `weighed` takes the tasks of session receipts that ended with an outcome and whose arm was decided, by arm, each with whether it succeeded and, when its agent's transcripts are read, its cumulative input, uncached input, turns and tool calls. `compare` sets the treated arm against the held-out one once each holds 30 such tasks: the success rates, and per successful task the medians of the four, each with the difference (treated minus held out) and its 95% percentile bootstrap interval, each arm resampled 2,000 times from a generator seeded by a hash of the values, so the same tasks always give the same interval; the medians only when each arm holds 30 successful tasks whose usage was read, and how many each arm holds either way (`per_success_tasks`) |
| `recorded`, `Recorded`, `Holdout`, `Selection`, `ReportError` | The receipts report both `cortex receipts` and the map show, read from a store: the held-out and treated arms with the 30 tasks each needs and their comparison once both have them, the precision of the labelled work orders and of the warnings, and the receipt of each session `Selection` names (one by id, or each started since a time), a subagent's work counted in its parent's. A session asked for that is not stored, or is a subagent, is refused by id |
| `Interval`, `mean_interval`, `ratio_interval` | A value with its 95% percentile bootstrap interval, resampled 2,000 times from a generator seeded by a hash of the values. `mean_interval` takes the mean of single values, a share being the mean of ones and zeros. `ratio_interval` takes a ratio of sums over groups, each a part and a whole such as one task's used and labelled work orders, and resamples whole groups, so outcomes that come together are drawn together; a resample with no whole has no ratio and is left out |
| `Arms`, `MIN_TASKS_PER_ARM` | How many of a repository's tasks were held out from Cortex and how many were not, and whether each arm has the 30 a comparison needs |
| `utc_millis`, `utc_text` | A transcript's time, `2026-11-02T23:04:17.241Z`, as UTC milliseconds, and back; anything else is no time |
| `MeterError` | A transcript that could not be measured or read |

## Tests

```sh
cargo test -p cortex-meter
```

The tests read three real Claude Code transcripts under `tests/fixtures/claude/2.1.316/transcripts`,
reduced to the fields a usage reader looks at and scrubbed: every response's counts are written out
by hand from the fixture, and their sums are checked against the running totals Claude Code
itself wrote: equal for a session without `/compact`, and for one with it short by exactly the
call that summarized the session, which no transcript line records and so is not counted. They read a transcript whole, cut short in the middle of
a line, in pieces cut anywhere (a property: the pieces give what the whole gives), written again
shorter, with a copy of a response raised and lowered, with a replayed and a synthetic response, with a line missing a count,
past the number of responses remembered, and with a line longer than a read. The pricing tests
check every model of the shipped table against its row copied by hand from the pricing page, work
costs out by hand (the cache's two lifetimes, fast mode in the United States, a long prompt either
side of its threshold, reached by input alone and by cache reads, a dated id), give every reason a
response has no estimate, refuse files that are not price tables (unknown keys, prices and
multipliers that are no price or too small to keep, dates that are no day, text that is not
UTF-8, a file too large), and write the shipped table once, privately and leaving nothing else
behind, then read the user's prices as they are. The receipts tests add up a session by hand:
responses at a task's start and end, between tasks, before any, in a task left open and from a
subagent, each unpriced reason, no price table, tasks listed out of order, tool calls in and
outside tasks, and each task's arm once decided.

A real Codex 0.166.0 rollout under `tests/fixtures/codex/0.166.0/rollouts`, scrubbed (ids fixed,
text replaced, numbers and types kept), is read for its eleven responses, each counted by hand;
their sum equals the running total Codex wrote in the same file. It is also read a line at a time
as Codex writes it, with lines missing each count in turn, an id, or a model before them.
