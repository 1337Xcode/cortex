# cortex-core

The types every other Cortex crate shares: repository paths, the repository id, content hashes,
the languages Cortex parses, the names the index may store, the kinds of record it keeps, scale
modes and settings.

## What it must never do

- Open sockets, read a repository's files, or depend on a crate that does. Every other crate
  depends on this one, including the hook client, which must start fast. Its calls to the file
  system resolve a folder to its canonical form (`canonical_root`), so that every crate names a
  repository the same way, and create the user's private folders and files and rotate the logs in
  them, so that the hook and the daemon do both the same way.
- Start a program unless a caller asks it to, through `capture` or `time_fed`; the hook client
  never does. They sit here because the CLI, the daemon and the git history all run other
  programs, and this is the one crate all of them may use.
- Accept a path that leaves the repository or a stored name that spans lines: these types are
  where those rules hold.

## Entry points

| Item | What it is |
| --- | --- |
| `RepoPath` | A path relative to the repository root with `/` separators; `from_native` converts a platform path inside the root, including Windows verbatim (`\\?\`) spellings |
| `canonical_root` | A folder in its canonical form: absolute, links and `..` resolved, names spelled as stored, no Windows verbatim prefix; every spelling of one folder gives one result |
| `RepoId` | The 16-character id of a repository on this machine, from the BLAKE3 hash of its canonical root |
| `ContentHash`, `ShortHash` | BLAKE3 hashes of 32 bytes (file contents) and 16 bytes (symbols, anchors); a content hash's first 16 bytes are the short hash of the same bytes (`short`); a short hash is written in stored facts as its 32 lower-case hexadecimal characters and read back from those alone (`from_hex`) |
| `FileContent` | What a file held at one moment, as the index saw it: no file, contents of a known hash, or contents the index does not read (a secret file, one past the size limit) |
| `Language`, `Tier` | The 21 languages and formats with their stored names; Tier A gets symbols, Tier B keys or headings |
| `without_ignore_block`, `IGNORE_BLOCK_HEADER`, `IGNORE_CORTEX_FOLDER`, `IGNORE_ALL_BUT_SHARED`, `IGNORE_LOCAL_SETTINGS` | The block `cortex init` adds at the end of a `.gitignore`: the comment `# Cortex`, then `.cortex/` (or `.cortex/*` and `!.cortex/shared/` when the team shares facts) and `.claude/settings.local.json`; and a `.gitignore`'s text without it, when its end is that block and nothing else, so that the work tree's look knows Cortex's own change |
| `Identifier` | A stored name: one line, at most 256 bytes, no control characters |
| `SymbolKind`, `RefKind`, `Resolution`, `NodeKind`, `EdgeType`, `FileFlags`, `InterestTier` | The kinds of record the index keeps, with the names, numbers and bits stored for them; a `Resolution` also gives the confidence of a reference resolved that way, and an `InterestTier` is which of the three levels of the map's fog a node's interest puts it in |
| `estimate_tokens` | How many model tokens a text Cortex injects is taken to be: its UTF-8 bytes over four, rounded up; every cap it sizes is also held in characters |
| `identifier_tokens` | Splits a name or a path into the lower-case words a search matches: at anything but a letter or a digit, at a capital after a small letter or a digit, and at the last capital of a run when a small letter follows (`parseHTTPRequest` gives `parse`, `http`, `request`) |
| `jaccard` | How alike two sets are: what they share over what they hold between them, from 0 to 1, and 0 for two empty sets; the one measure task clustering, prompt-to-task matching and fact merging use |
| `GateFeatures`, `ReasonKind` | What an injection is made of, as each crate that handles one sees it: the numbers the gate weighs (top lexical score, the top five files' share of the activation, the kinds of evidence agreeing on one top file and supporting any, the likeness to earlier work, the recent precision, whether the session continues its own work), and the kinds of reasons a file is listed for, by fixed names, without the words a reason says |
| `WarningKind` | What a warning after an edit points out, with the name storage keeps it by: `cochange` (a file that usually changes with the edited one, not touched yet), `call_site` (a changed signature still called from other files), `test` (the edited file's tests, not touched yet) |
| `task_id_of_prompt`, `is_held_out` | The id of the task a prompt starts, made at the prompt's time from its event's id, so the daemon answering the prompt and the writer recording it name the task alike; and whether a task is held out from Cortex's injections: a BLAKE3 hash of its id, derived under a context of its own, read as a fraction of 2^64 and compared with `holdout.share`, so a larger share keeps every task a smaller one held |
| `ScaleMode` | `tiny`, `small`, `medium` or `huge`: how fully a repository of a given size is served |
| `Event` | One hook call, normalized: the agent, its session, the point in its loop (`HookKind`), the tool (`ToolKind`), what the tool aimed at (`ToolTarget`: a repository path, checked `LineRange`s, a pattern, a `ShellCommand` cut to 1,000 characters, and the files a search found inside the repository, at most `MAX_HITS` (50) of them and `MAX_HITS_BYTES` (4 KiB) of paths, which travel to the daemon and are never stored) and how it ended (`ToolResult`: exit code, success, interruption, output size), and whether it is a probe (`cortex doctor`'s synthetic call, which a daemon answers and does not record), never file contents or tool output; serialized with names for every kind and checked when read. `Event::edited_file` is the file a successful edit's result changed (`ToolKind::is_edit`: an edit, a write, several edits or a patch), and `Event::file_to_read` the file a read is about to read, at the moment before it runs, and `Event::prompt_for_work` a prompt that may ask for code (not a slash command, `/` first, nor a shell escape, `!` first, and at least `MIN_WORK_PROMPT_CHARS`, 4, characters other than spaces): the one definition of each the hook and the daemon share |
| `SessionStatus`, `TaskOutcome`, `EventKind`, `EventSource`, `CommandKind`, `EventMeta`, `PromptExcerpt` | What the store keeps of agents' activity: a session's status, a task's outcome, an event row's kind and source, the facts an event keeps besides its path and lines (tool, exit code, success, interruption, output size, why a session started or ended, what started a compaction, a subagent's type, for a shell command the runner and kind of the check it ran: tests, a build, types or lint, never the command, and for a read the short hash of what the index held for its file), and the first 200 characters of a prompt kept only on request |
| `Ulid` | A sortable unique id: UTC milliseconds, then 80 bits from the BLAKE3 hash of a seed the caller gives; written as 26 characters, and only that spelling is read back |
| `unix_millis` | A clock time as UTC milliseconds since 1970, the unit the store and the protocol use; a clock set before 1970 reads as 0 |
| `rotate_log` | Makes room for a new log: each older file moves one place (`.1` to `.2`, the oldest kept replaced) and the log moves to `.1` |
| `create_private_folder`, `open_private_file`, `append_private_file` | Folders and files only the user can read: mode 0700 and 0600 on Unix, whatever the umask, a wider mode narrowed; on Windows the access list they inherit |
| `REMINDER_TAGS`, `holds_reminder_tag` | The tags agents keep for their own reminders (Claude Code's `system-reminder`, opening and closing), and whether a text holds one in any case: text Cortex gives an agent never does |
| `AGENT_SHELL_MARKERS`, `is_agent_shell` | Whether a command runs inside a coding agent's shell rather than a person's terminal: the variables Claude Code sets on the commands its tools and hooks run (`CLAUDE_CODE_CHILD_SESSION`) and those Codex sets on its shell commands (`CODEX_THREAD_ID`, `CODEX_TOOL_CALL_ID`), any of them set and not empty |
| `is_plain`, `is_taken_out` | Whether a text can be put in front of an agent as it is: no control character but a tab, no character that reorders or hides text, and no reminder tag. Every text Cortex writes for an agent (work orders, the primer, hints, recaps, warnings, coordination notices) holds the repository's paths and names to this one check, so a crafted file name cannot add a line, a hidden instruction or a tag |
| `FactKind`, `FactSource`, `FactStatus`, `MAX_FACT_CHARS`, `MAX_FACT_ANCHORS` | A fact: one project rule of at most 240 characters, about at most 16 files and symbols. Its kind (convention, decision, invariant, pitfall, ownership), who wrote it (the user, an agent, a team import) and where it stands (candidate, active, suspect, retired); the user's start active and every other source's as candidates, and only an active fact is injected |
| `PositionMode` | What a session did to a node of the map, as coordination keeps it: read, edit or claim |
| `NoticeSubject` | What a coordination notice is about apart from its words (the agent, the file, what it did there, whether at once with the session told, the signatures it changed), and whether a notice already sent covers a new one: the same hold, naming no changed signature the sent one does not |
| `Agent::title` | An agent's name as people write it (`Claude Code`, `Codex`, `Gemini CLI`), the one place text names an agent |
| `one_line`, `is_hidden` | Text for a log or a report a person reads: its first characters up to a limit, each control character and each character that reorders or hides text (bidirectional controls, zero-width characters, the byte order mark) written as a space, so that no text that reached it can split the line, steer a terminal or read differently from what it holds; `is_hidden` tells whether a character changes how the text around it shows without showing itself (bidirectional controls, zero-width characters, separators, the byte order mark, tag characters) |
| `ipc` | The messages the hook, the CLI and a daemon exchange (`Request`, `Response`, the `Hello` handshake), framed as a 4-byte little-endian length and at most 1 MiB of JSON (`encode`, `decode`, `read_frame`, `write_frame`); `Protocol` (majors must match), `CortexVersion` (ordered as semantic versioning orders versions, and written as read less its build metadata) and `is_older_than_this_build` (false for a version that does not read, so no build replaces what it cannot rank). The envelope, `Hello`, `Mismatch` and `Shutdown` never change shape. The requests answered with text, `Retrieve` (the work order), `Primer`, `PostEdit` (an edit's warnings, from protocol 3.0), `ReadHint` (a read's hint, from protocol 4.0) and `StopReason` (strict mode's reason at a stop, from protocol 5.0), say until when their hook reads the answer (`answer_by_ms`, in UTC milliseconds, from protocol 2.1). A read's target says where the agent's tool cut a whole-file read short (`cut_after`, from protocol 5.1). From protocol 6.0, `Note` (a fact noted: its text, kind, who notes it, the user or an agent, from 7.0, and anchors, each a repository path and optionally `:` and a symbol) and `Facts` (`FactsAsk`: list, confirm, retire or edit by number) are answered with `Facts` (`FactsAnswer`: the facts listed as `FactLine`s, what became of a note as a `NoteOutcome`, or the fact confirmed, retired or corrected). From protocol 8.0, `Why` (a target: a repository path, that path and `:line` or `:symbol`, or a symbol's name) is answered with the text, or an error saying why the target names nothing. From protocol 9.0, `Claims` (`ClaimsAsk`: list, add files, release files or all) is answered with `Claims` (`ClaimsAnswer`: the claims listed as `ClaimLine`s, the files claimed and the session holding them, or how many were released). From protocol 10.0, `Consolidate` asks for upkeep now, answered at once with `Ack`, and the status carries what the last run of upkeep removed and whether it finished (`UpkeepReport`; from 10.1 with the free pages it gave back, read as 0 from a 10.0 daemon). From 10.2 a tool's target may carry the end of a failed command's output (`failed_output`, at most `MAX_FAILED_OUTPUT_BYTES`), which a daemon before 10.2 ignores |
| `UserFolder`, `RunFiles`, `Endpoint` | `~/.cortex` and what it holds: `config.toml`, `logs/`, and per repository id the daemon's socket (`run/<id>.sock`), named pipe (`cortex-<id>`), lock and process-id files; the endpoint a daemon listens on here, its named pipe on Windows and its socket elsewhere |
| `Config`, `load_config`, `config_keys_set` | The settings in effect: defaults, then `~/.cortex/config.toml`, then `.cortex/config.toml`, each a `ConfigLayer`; unknown keys warn, and unusable values are errors naming the file and key. `config_keys_set` lists the keys a file sets. Keys: `mode`, `index.max_file_bytes`, `index.extra_ignores`, `index.parse_timeout_ms`, `index.crawl_files_per_second`, `daemon.idle_shutdown_minutes`, `store.mmap_bytes`, `privacy.store_prompt_excerpt`, `holdout.share` (a number from 0 to 1, whole numbers 0 and 1 included), `learning.eta`, `learning.link_decay` and `learning.interest_decay` (each above 0 and at most 1), `git.max_commits`, `git.max_age_days`, `git.max_files_per_commit`, `git.half_life_commits`, `tests.extra_patterns` (regular expressions, each checked when the file is read), and the `RetrievalConfig` keys: `retrieval.max_tokens` (900, at most the work order's hard cap of 1,200, `MAX_WORK_ORDER_TOKENS`), `retrieval.max_files` (5, at most 20), `retrieval.max_code_spans` (2, at most 5), `retrieval.span_max_lines` (60, at most 200), `retrieval.teleport` (0.5, above 0 and at most 1), `retrieval.min_confidence` (0.70, from 0.5 to 1: the chance a kept confidence model must give a work order; small mode asks at least 0.85) and `retrieval.type_weights` (`TypeWeights`: `structural` 1.0, `cochange` 0.6, `coaccess` 0.8, `about` 1.0, `containment` 0.1, each from 0 to 1), the `WarningsConfig` keys: `warnings.max_per_edit` (3, from 0 to 10), `warnings.cochange_min_confidence` (0.5, from 0 to 1), `warnings.cochange_min_count` (3, above 0), `warnings.cochange_min_link_weight` (1.0, 0 or more: the faded weight of a link of agents' past work) and `warnings.cochange_min_link_tasks` (3, above 0), the `CoordinationConfig` keys: `coordination.read_minutes` (10), `coordination.edit_minutes` (30), `coordination.edit_after_task_minutes` (5), `coordination.claim_minutes` (120), `coordination.live_minutes` (15), `coordination.same_file_minutes` (10) and `coordination.handoff_idle_minutes` (30, how long a session that never ended must be quiet before its handoff is given), each from 1 to 1,440, `coordination.structural_min_weight` (0.8) and `coordination.cochange_min_confidence` (0.5), each from 0 to 1, `coordination.max_notices` (3, from 0 to 10) and `coordination.max_tokens` (200, from 1 to 400), `strict_mode` (false: when true, a task's agent that stops while files calling a signature it changed were not read or edited since the warning is given a reason to go on, once a task) and `hints.runtime_grounding` (false: when true, a failed check is given the repository lines its stack ran through) |
| `read_text_file`, `TextFileError`, `MAX_SETTINGS_BYTES` | Reads a small text file whole, such as a configuration or settings file, up to a size its reader names (1 MiB for those): read once, a byte past the limit, so that the file cannot grow between a check and the read; `None` when there is no file, and refused when it is larger or not UTF-8 |
| `find_program`, `GIT` | The first program of the names given (`GIT`: git's on this platform) in the folders the `PATH` lists, as a shell finds it, never one inside the repository or in a relative folder of the `PATH`, which could be the repository |
| `capture`, `Captured` | Runs a program with no input and stderr discarded, keeps at most a given number of bytes of its stdout (and whether there was more), and gives it a timeout from its start to end and close its stdout, stopping it past that; a process it started that holds the output open is not waited for. `NotFound` when it is not installed, `TimedOut` past the timeout |
| `time_fed` | Runs a program with an input on its stdin and its output discarded, and returns how it ended and how long it took from just before its start to its end, as an agent sees a hook take. A thread of its own writes the input and waits for it, so a program that neither reads nor ends is given up on at the timeout (`TimedOut`) and left to end on its own; one that ends without reading all of its input is timed all the same |
